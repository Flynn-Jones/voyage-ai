# RAG Tool Contracts

Shared local RAG server (not containerised). Containerised backends call it at
`http://host.docker.internal:7002/<refresh|retrieve|answer>`.

Corpus sources (env var names): Destination DB API (`DESTINATION_DB_URL`, default
`http://localhost:6001`, tier_1), Budget DB API (`BUDGET_DB_URL`), Accommodation DB API
(`ACCOMMODATION_DB_URL`), Itinerary DB API (`ITINERARY_DB_URL`, tier_1), factual repo docs
(tier_2; READMEs with demo prompts/usage examples are excluded) and a repository file index (tier_3). Databases are read only through their HTTP APIs, never through SQLite.
Generation uses `OLLAMA_GENERATE_URL` and `OLLAMA_MODEL`.

## Retrieval acceptance
Relevance decides what is returned; authority tier only breaks ties.
- Query terms: alphanumeric tokens (length > 1) minus a fixed stopword list, with light plural folding.
- A chunk is accepted when it shares at least one term and either
  (>= 2 shared terms and shared/query terms >= 0.5) or a shared term is a Destination city/country.
- Zero-overlap chunks are never returned. Ranking: relevance score, matched-term count, vector distance, tier.
- Candidates are the full corpus; Chroma supplies `distance` when available (`retrieval_mode`: `hybrid`,
  or `lexical_fallback` if the vector store fails).

## refresh_corpus
- Purpose: rebuild the corpus and vector index
- Input: `caller` (optional)
- Output: `status`, `chunk_count`, `collection`, `vector_store_status`, `source_status`
  (`destination_db` / `budget_db` / `accommodation_db` / `itinerary_db`: `"ok"` or `"unavailable: <error>"`),
  `missing_docs`, `itinerary_chunk_count`, `itinerary_source_error`.
  An unavailable source contributes no chunks.

## retrieve_context
- Input: `query` (required), `k` (optional, default 5), `caller` (optional); scoped extension below
- Output: `status`, `retrieval_mode`, `candidate_count`, `rejected_count`, `results[]` with `rank`, `chunk_id`,
  `source_id`, `authority_tier`, `distance`, `text`, `relevance_score`, `matched_terms`.
  `results` may be empty (valid).

## answer_question
- Input: `query` (required), `k` (optional), `caller` (optional); scoped extension below
- Output always has `status`, `query`, `answer`, `citations[]`, `confidence_category`.

| Case | `status` | HTTP | `confidence_category` |
|---|---|---|---|
| Grounded answer | `success` | 200 | `High` / `Medium` / `Low` |
| No accepted context, or the model replies "Insufficient evidence" | `insufficient_context` | 200 | `Insufficient` (`citations: []`, no unsupported answer) |
| Ollama unreachable / non-2xx / error body / empty reply | `error`, `error_type: llm_unavailable` | 503 | `null` (`answer: null`) |
| Retrieval failure | `error`, `error_type: retrieval_failed` | 500 | `null` (`answer: null`) |

- `retrieval_summary`: `k`, `retrieved_count` (accepted), `candidate_count`, `rejected_count`,
  `retrieval_mode`, `top_score`. Present on success, insufficient_context and llm_unavailable.
- Confidence: `High` = top score >= 0.75 and >= 2 accepted chunks; `Medium` = top score >= 0.5 with >= 2 matched terms;
  `Low` = anything else accepted (e.g. a city-name-only match) or tier_3-only evidence.
- Ollama is not called when nothing is accepted.

## Student 5 scoped extension (`scope="itinerary"`)

Existing callers can omit the new parameters. HTTP `/retrieve` and `/answer`,
and their stdio equivalents, also accept `scope="itinerary"`, required
`trip_reference`, and optional positive integer `day`. The scoped path validates
query length (1–1000), trip length (1–120), and integer `k` (1–20).

Refresh now reads `ITINERARY_DB_URL` (default `http://localhost:6005`) over HTTP.
Each itinerary chunk retains the full record, trip/day metadata, item ID,
`indexed_at`, and source `itinerary-db:/itinerary-items`. Refresh adds
`itinerary_chunk_count` and nullable `itinerary_source_error` to its response.
A failed itinerary source does not stop other students' corpus refresh, and is
never indexed as itinerary evidence. The Student 5 backend surfaces that failure.

Scoped retrieval uses exact trip/day metadata and a conservative supported-question
vocabulary for schedule and estimated-cost questions. It does not rely on the
legacy hash embedding's relevance. Unknown topics, conflicting days/trips, and
missing records abstain with `confidence_category="Insufficient"`, no citations,
and no model call. Example: `What activities are planned?` or
`What is the estimated itinerary cost?`, with a separate trip reference.

`/retrieve` returns up to k matching records and `matched_count`. `/answer` uses
all matching records, including when k is smaller, to prevent truncated totals.
When evidence is sufficient, the final answer is generated by the configured
local Ollama model (`OLLAMA_MODEL`, `OLLAMA_GENERATE_URL`), with `answer_source=
"llm"` and `model`. The prompt contains only scoped records and deterministic
facts calculated from those records (including complete cost totals). It prohibits
outside knowledge and instructs the model to abstain if context cannot support
an answer. Citations are created by the server from the exact supplied chunks;
model-supplied citation/confidence fields are never used. Confidence remains
evidence-derived: High for supported exact-scope evidence, Insufficient for
missing/unsupported evidence or model abstention. This is confidence in the
retrieved snapshot, not a guarantee of model correctness or freshness.
Answers preserve `answer`, `citations`, and `confidence_category`; they add trip,
day and retrieval summary. Missing evidence/invalid costs bypass the model.
Model timeout, HTTP failure, invalid JSON or empty output returns `status="error"`
and `error_type="llm_unavailable"`; no deterministic success fallback is returned.
The shared HTTP wrapper returns 503 (see `answer_question`) and the itinerary backend maps this to 502.
Scoped generation uses temperature 0, a 256-token output limit and a 90-second
timeout. An explicit model abstention returns Insufficient with no citations.

The unscoped path (all other callers) keeps the relevance acceptance and confidence
rules above; its Ollama failure returns `status="error"`, `error_type="llm_unavailable"`.
Unlike the unscoped path, a scoped abstention keeps `status="success"` with
`confidence_category="Insufficient"` and no citations.
Chroma is imported lazily so structured itinerary retrieval can operate while
the vector store is unavailable; refresh reports `vector_store_status="degraded"`.
`RAG_DATA_DIR` optionally relocates corpus, audit and Chroma files (default unchanged).
Refresh after itinerary changes; there is no automatic change notification.

## Audit
Every call appends to `rag-audit.jsonl` (`request_id`, `tool_name`, `tool_input`, `tool_output`, `timestamp`,
`duration_ms`, `validation_status`, `outcome`). Answer outcomes: `answer_generated`, `insufficient_context`,
`llm_declined`, `llm_unavailable`, `retrieval_failed`. A failed audit write never fails the call.
